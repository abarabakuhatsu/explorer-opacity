# 1. 透明度方式: レイヤード alpha を既定とし backdrop を選択肢化

* ステータス: 承認
* 日付: 2026-10-01
* 決定者: ユーザー + AIエージェント

## コンテキスト（背景）
Explorer ウィンドウを半透明にする方法は大きく2つある。

1. `SetLayeredWindowAttributes`（`WS_EX_LAYERED` + `LWA_ALPHA`）: ウィンドウ合成結果全体に
   一様な alpha を掛ける。透明度を任意の % で指定できるが、**文字を含む全要素が半透明**に
   なる。
2. DWM システムバックドロップ（`DWMWA_SYSTEMBACKDROP_TYPE` = Acrylic/Mica）: 背景素材を
   DWM が描画する。**文字は不透明のまま**だが、透明度はプリセットで任意 % 指定はできない。

原案（AutoHotkey）は方式1を採用しており、文字が透ける問題が残る。一方、方式2は非アクティブ
時の解除が要件と衝突しうる（特に AccentPolicy 系）。

## 決定事項（Decision）
* **既定方式を方式1（レイヤード alpha）とする**。任意の不透明度 % を優先するため。
* 方式2（backdrop）は `mode = "backdrop"` として実装し、設定で切替可能にする。
* `SetWindowCompositionAttribute` の AccentPolicy acrylic は**主方式にしない**（非アクティブで
  ぼかしが解除される既知挙動があり、「非アクティブでも透明化を継続」と矛盾するため）。
* 文字が透ける問題は方式1では原理的に回避不能であることを受け入れる。

## 影響・結果（Consequences）
### ポジティブな影響
* 任意の不透明度（既定 85%）をユーザーが制御できる。
* 全 Windows で動作し、非アクティブでも透過が維持される。
* mode 切替により、文字の鮮明さを優先したいユーザーにも道を残せる。

### ネガティブな影響・トレードオフ
* 方式1では文字が半透明になり可読性が下がる。
* 方式2は Windows 11 build 22621+ 限定で、透明度の % 指定ができない。
* 2方式分の状態管理・復元処理が必要になり複雑度が増す。

## 追記（2026-10-01）
実機検証（ADR-0004）により方式2（backdrop）は Explorer の本文領域を透明化できないと判明
したため不採用となり、方式2に関連する選択肢は ADR-0005 で削除された。以降は方式1（alpha）を
唯一の方式とする。また方式1で懸念していた「文字の半透明」は、既定 85% では実用上の問題が
ないことを確認した。
