# 2. ウィンドウ検知: シェルフック + 低頻度セーフティ掃引

* ステータス: 承認
* 日付: 2026-10-01
* 決定者: ユーザー + AIエージェント

## コンテキスト（背景）
原案は 500ms 周期のポーリングで Explorer を検出していた。常駐負荷を下げるにはイベント駆動が
望ましいが、イベントのみには取りこぼしの懸念がある。

* `RegisterShellHookWindow` の `HSHELL_WINDOWCREATED` は新規トップレベルウィンドウ生成を
  通知するが、生成直後に Explorer がスタイルを上書きすると通知だけでは追従できない。
* `explorer.exe` が再起動するとシェルフック登録が失われ、トレイアイコンも消える。
* 最大化・スナップ・テーマ変更などで alpha が失われるケースを捕捉するイベントは無い。

## 決定事項（Decision）
* 主検知は `RegisterShellHookWindow` のイベント駆動とする。
* 併せて **30 秒周期のセーフティ掃引**（`SetTimer` + `EnumWindows`）を実行し、取りこぼしを
  回復する。
* `TaskbarCreated` メッセージを受信したら、**トレイ再登録・シェルフック再登録・再掃引**を
  行う（Explorer 再起動対策）。
* 起動時にも一度全探索する。

## 影響・結果（Consequences）
### ポジティブな影響
* 待機時の CPU 使用はほぼゼロ（イベント駆動）。
* Explorer 再起動・スタイル上書き・イベント取りこぼしのいずれにも追従できる。
* ポーリングを 30 秒に間引くことで、原案の 500ms ポーリングより大幅に軽量。

### ネガティブな影響・トレードオフ
* シェルフックが死んだ場合は最大 30 秒間、新規ウィンドウが透過されない。
* イベントとタイマーの二経路があり、テスト・デバッグ対象が増える。
