# 3. 実装スタック: Rust + windows-sys

* ステータス: 承認
* 日付: 2026-10-01
* 決定者: ユーザー + AIエージェント

## コンテキスト（背景）
軽量な常駐ツールを配布する必要がある。候補は AutoHotkey v2（原案）、Rust、C#/.NET、C/C++。

* AutoHotkey: 最速で動くが 500ms ポーリングで常時 CPU を消費し、配布にランタイムが要る。
* C#/.NET: 型安全だが成果物が大きく、ビルド構成が重い。
* C/C++: 最小だがコンパイラ未導入（`cl`/`clang` なし）。
* Rust: 単一 exe・ランタイム不要・Win32 直叩き・イベント駆動で極小負荷。

環境実測（2026-10-01, Windows 11 build 26200）: `rustc 1.98.1`（host `x86_64-pc-windows-msvc`）
で `cargo build` が成功し、crates.io へ到達可能。

## 決定事項（Decision）
* **Rust 2021 + `windows-sys 0.59`** を採用する。`HWND` 等は生ポインタで扱い、Win32 API を
  直接呼ぶ。
* 依存は `windows-sys` と `serde` + `toml`（設定ファイル）に限定する。
* 成果物は単一 exe（`--release` + LTO + `strip`）。ポータブル運用とし、設定は exe 隣に置く。
* MSVC リンカが利用できない環境向けに、`x86_64-pc-windows-gnu` ターゲット + MinGW への
  フォールバックを選択肢として記録する。

## 影響・結果（Consequences）
### ポジティブな影響
* 単一 exe（実測 約 395 KB）でランタイム不要、待機 CPU ほぼゼロ。
* イベント駆動・トレイ・ホットキー・レジストリをすべてネイティブ API で実装できる。
* 純関数（フィルタ・設定・ホットキー解析）をユニットテスト可能。

### ネガティブな影響・トレードオフ
* Win32 の unsafe コードが中心となり、保守には Windows API 知識が要る。
* ビルド環境に MSVC リンカ（または GNU ツールチェーン）が必要。
* `windows-sys` は世代ごとに API 型が変わるため、バージョン固定が望ましい。
