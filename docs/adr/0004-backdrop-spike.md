# 4. backdrop 方式は不採用、alpha 方式を採用する

* ステータス: 承認
* 日付: 2026-10-01
* 決定者: ユーザー + AIエージェント

## コンテキスト（背景）
文字を不透明に保つため DWM システムバックドロップ（Acrylic/Mica）が候補だった（ADR-0001）。
`eo-spike` で実機（Windows 11 build 26200）比較した結果、次の事実が判明した。

- `eo-spike acrylic` / `eo-spike mica` は **タイトルバーとメニューバーのみ**に効果が現れ、
  ファイル一覧などのクライアント領域は透明にならなかった。
- 理由: DWM バックドロップは「ウィンドウが透明に描画した領域の背後」にしか描かれない。
  Explorer のクライアント領域は自前で不透明に描画するため、外部から
  `DWMWA_SYSTEMBACKDROP_TYPE` を設定しても本文領域には透けない。
  `DwmExtendFrameIntoClientArea` を併用しても、アプリ側が上から塗るため覆せない。
- 一方 `eo-spike alpha` は **ウィンドウ全体がきれいに透明化**し、85%（alpha 217）では
  **文字の可読性にも実用上の違和感がなかった**。
- 非アクティブでも透過が維持されることも確認できた。

## 決定事項（Decision）
- **backdrop 方式（Acrylic/Mica/AccentPolicy）は不採用とする。**
- **alpha 方式（`SetLayeredWindowAttributes` + `LWA_ALPHA`）を唯一の方式として採用する。**
- 既定の不透明度は **85%** とする（低くすると文字が読みにくくなるため）。
- backdrop に関連するコード・設定・UX は削除する（ADR-0005）。

## 影響・結果（Consequences）
### ポジティブな影響
- 要件（ウィンドウ全体の透過・非アクティブ維持・新規窓/再起動追従・終了復元）を alpha 単独で
  満たせる。
- 方式分岐・モード切替・backdrop の状態管理が不要になり、実装と設定が大幅に簡素化。
- 依存（`windows-sys` の DWM/Controls 機能）と exe サイズを削減できる。

### ネガティブな影響・トレードオフ
- 文字も半透明になる（85% では実用上問題ないが、より低い不透明度では可読性が落ちる）。
- 背景は「ぼかし」されず、単純に透ける（Acrylic の質感は得られない）。
